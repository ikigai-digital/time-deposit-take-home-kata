# AI-assisted development

## Tools and setup

| Part | What was used |
|---|---|
| Coding agent | [Claude Code](https://docs.claude.com/en/docs/claude-code/overview), in the Claude desktop app (Code tab) on Windows 11 |
| Model | Claude Opus 5.5 (`claude-opus-5-5`) |
| Agent tools | File read/write/edit, shell (Git Bash and PowerShell), built-in browser pane to check Swagger UI |
| Project rules | [`CLAUDE.md`](CLAUDE.md), loaded automatically by Claude Code in this repository |
| Permissions | [`.claude/settings.json`](.claude/settings.json): Maven Wrapper, read-only git and Docker commands are allowed without prompts. `git push` and edits to `TimeDeposit` and the legacy reference calculator are denied. |
| Developer's global rules | Personal Claude Code instructions applied to every project: no code comments, team naming and exception-handling rules for Java, show a per-file plan and get approval before writing code, commit and push only on explicit approval. The project-relevant parts are copied into `CLAUDE.md`, so the setup works for anyone who clones the repo. |

### Reproduce the setup

1. Install Claude Code (desktop app or `npm install -g @anthropic-ai/claude-code`) and sign in.
2. Clone this repository and start Claude Code in its root folder. `CLAUDE.md` and `.claude/settings.json` are picked up automatically.
3. Start Docker, so the agent can run `./mvnw verify` including Testcontainers.
4. Give the agent a task in plain language, for example "Add a new plan type 'gold' with 4% interest". The rules make it present a plan first, change the code test first and run the full build before it reports back.

## Workflow

1. **Analysis:** the agent read the assignment README and the original Java sources and summarised the requirements and constraints.
2. **Plan approval:** the agent proposed the architecture, the endpoint design and a per-file change list. The developer reviewed and approved it before any code was written (the rule from `CLAUDE.md`, workflow step 1).
3. **Safety net first:** the original calculator was copied verbatim into test sources as `LegacyTimeDepositCalculator`, and a parameterized characterization test compares old and new behaviour on 616 combinations of plan type, boundary days and balances.
4. **Implementation by layer:** domain policies, then the application service and ports, then the contract and REST adapter, then persistence and migrations. The build was compiled after each step.
5. **Verification:** `./mvnw verify` with Testcontainers, then the app was started with Docker Compose, both endpoints were called with curl and Swagger UI was checked in the browser pane. A port conflict found this way (local PostgreSQL on 5432) led to publishing the Compose port on a random host port.
6. **Review:** the developer reviewed the diff and the commits before pushing.

## What was AI-assisted and why

| Area | AI involvement | Why |
|---|---|---|
| Requirement analysis and design | Proposed by the agent, decided by the developer | Fast way to get a complete first design. Design choices (endpoint semantics, table naming, where the 30-day rule lives) stayed a human decision. |
| Interest policy refactoring | Generated by the agent | Mechanical refactoring that is fully protected by the characterization tests. |
| Characterization tests | Generated by the agent | Exhaustive boundary combinations are tedious to write by hand and easy to generate. |
| OpenAPI contract, REST and persistence adapters, Flyway migrations | Generated by the agent | Boilerplate following standard Spring patterns. |
| Integration tests (Testcontainers) | Generated by the agent | Expected balances were hand-calculated and cross-checked against the unit tests. |
| Running and checking the app | Done by the agent | The agent ran the build, the app, curl calls and Swagger UI itself, so the reported result is verified rather than assumed. |
| Documentation | Drafted by the agent, reviewed by the developer | The README, assumptions and this file. |

AI output was never accepted without the build passing: every change had to keep `./mvnw verify` green.
